# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [2.0.0] - 2026-10-14

### Security

- **New installations did not check the LDAP password or the CRL.** `init-openvpn.sh` wrote a `server.conf` without `auth-user-pass-verify` and `crl-verify` (since 1.0.0), so a certificate alone was enough to connect — the password the client asked for was never checked — and revoking a certificate in the WebUI did not stop it from connecting. `start-openvpn.sh` now writes the LDAP check, the CRL check and the cipher settings into `server.conf` on every start, replacing any hand-written copies, and regenerates the CRL so it always exists.
- **Compression (`comp-lzo`) is removed** from the server configuration (VORACLE).
- **LDAP search filter**: the username sent by the VPN client is now escaped before it is put into `LDAP_USER_FILTER`, so characters such as `*` or `)` can no longer change the search.
- **CSV exports** (audit log, VPN connection history) now quote every field properly and neutralise cells starting with `=`, `+`, `-` or `@`, so a crafted User-Agent cannot break the columns or run as a spreadsheet formula.
- The WebUI prints a warning at start when `TRUSTED_PROXIES` is empty (identity headers accepted from any source).

### Added

- **`LDAP_TLS_CA_FILE`** (optional): verify the LDAP server's certificate during StartTLS. Empty keeps the previous behaviour.
- **`FULL_TUNNEL`** (optional, default `false`): route all client traffic through the VPN (`redirect-gateway def1 bypass-dhcp` and `block-ipv6`).

### Changed

- The compose default for `EASYRSA_CRL_DAYS` is now 3650 (was 180, which expired the CRL and blocked every client after six months).

### Upgrading

Breaking for installations created with `init-openvpn.sh` that were never hand-fixed: after restarting `openvpn-server`, every connection needs a valid LDAP password from a member of `LDAP_VPN_GROUP`, and revoked certificates are refused. If `LDAP_SERVER` is empty, every login is rejected. Check the LDAP settings in `.env` before restarting. Clients that had compression enabled must remove `comp-lzo` from their profile (profiles generated by this project never had it).

## [1.3.0] - 2026-10-04

### Changed

- **Single-domain mode is now the default**: with `ADMIN_DOMAIN` empty, the user portal is at `/` and the admin portal at `/admin` on the same host, and admins can also request their own certificates there. Previously an empty `ADMIN_DOMAIN` left the admin portal unreachable. Setting `ADMIN_DOMAIN` and `USER_DOMAIN` keeps the previous split-domain behaviour unchanged. In split-domain mode `USER_DOMAIN` is now required; the WebUI refuses to start without it. See docs/CONFIGURATION.md and the Authelia path-rule example in docs/SETUP.md.
- **Mobile layout**: on narrow screens every table is shown as one card per row with field labels, and action buttons (download, approve, revoke, …) are full-width at the bottom of each card instead of at the far right of a horizontally scrolling table. Confirmation dialogs fit the screen. The desktop layout is unchanged.

### Security

- **Device names are now validated on the server** (letters, digits, `-`, `_`, up to 50 characters — the rule the form already showed). Only the browser checked it before, so a crafted request could store a device name that broke out of the revoke/reapprove button handlers on the admin certificate list and ran script in the admin's browser. Those handlers now also pass values as JSON instead of quoted strings.

## [1.2.2] - 2026-10-04

### Security

- **Updated WebUI dependencies with known vulnerabilities**: gunicorn 21.2.0 → 26.2.0 (HTTP request smuggling), Werkzeug 3.0.1 → 3.1.9, Jinja2 3.1.2 → 3.1.6 (sandbox breakout, attribute injection), Flask 3.0.0 → 3.1.3. `requests` is now pinned (2.34.2). Rebuild the WebUI image to apply (`podman compose build vpn-webui`).
- **Removed the unused `cryptography` dependency**: the WebUI never imported it (certificate operations run in the OpenVPN container through EasyRSA), and the pinned 41.0.7 carried several known vulnerabilities.

### Fixed

- **Username filters on the revoked-certificates and audit-log pages failed with an SQL error** (`ESCAPE expression must be a single character`) since 1.2.0, so filtering by username always fell back to an error. The LIKE escape character is now passed correctly.

## [1.2.1] - 2026-09-29

### Security

- **New `TRUSTED_PROXIES` setting**: the WebUI trusted `Remote-User` / `Remote-Groups` from any source, so a host that could reach the WebUI port directly could forge them and open the admin interface. When `TRUSTED_PROXIES` is set, identity headers are accepted only from the listed proxy addresses; other requests are treated as unauthenticated. Setting it is strongly recommended (see docs/CONFIGURATION.md).

### Fixed

- `ADMIN_GROUP` from `.env` is now passed to the WebUI container (previously compose.yml did not pass it, so the default `net-vpn-admins` was always used).

## [1.2.0] - 2026-07-20

### Added

- **Connection history filtering now works**: the period, date range, username, certificate name (partial match) and connection status filters are applied to the history table, the summary cards, pagination and CSV export. Previously the filter form was displayed but had no effect. All conditions are bound as SQL parameters; partial-match input is LIKE-escaped.
- **CSV export now contains data**: the exported file previously contained placeholder text only; it now includes a header row and all connection records matching the current filters.
- **Complete English/Japanese localization**: every page (dashboard, certificate request, certificate lists, audit log, connection history, system status) now follows the language selector, including flash messages and audit-log action names. Previously most pages were hard-coded in Japanese, and some messages displayed raw translation keys.

### Changed

- **Shared template components**: statistics cards, pagination, audit action badges and the custom-period date-picker behavior are now Jinja macros shared across admin pages, and per-page inline styling has been migrated to the common stylesheet, so all admin pages share one consistent look. Filter period options now use the same wording on every page.
- Translation catalogs were cleaned up: unused entries removed, missing entries added, and the English and Japanese catalogs are verified to contain the same key set.

### Fixed

- **Date fields no longer overflow on mobile**: form inputs are capped to the container width, and form fields keep a 16px font size on small screens so iOS no longer zooms in when they receive focus.
- Error messages that rendered a literal `%(error)s` placeholder now display the actual error text.
- The `vpn_connections` table schema now includes the `disconnection_type` column for new installations (the log parser already wrote it; existing databases are migrated automatically at startup if the column is missing).

## [1.1.2] - 2026-07-20

### Fixed

- **Connection history summary cards were blank**: the connection-history view passed an empty statistics context, so the "total connections", "currently connected" and "unique users" cards showed no values. The view now computes these aggregates and the cards display real numbers.
- **Mobile layout of the connection history page**: summary cards and the filter fields now stack in a single column on small screens instead of being squeezed into narrow half-width columns; the pagination bar wraps onto multiple rows so the previous/next controls are no longer clipped off-screen; and filter/export buttons wrap instead of breaking their labels across lines.

## [1.1.1] - 2026-07-19

### Fixed

- **VPN connection history page no longer redirects away**: the admin connection-history view raised a template error and bounced back to the home page because its pagination context was incomplete (missing `per_page`/`has_prev`/`has_next`/`prev_page`/`next_page`) and the filter context was empty. The page now renders the history table with working pagination.
- **Mobile table readability**: table cells in scrollable tables no longer wrap onto multiple lines on small screens; each row stays on one line and the table scrolls horizontally.

### Changed

- Removed the redundant "Admin Home" / "Back to admin" buttons from admin content pages (certificate list, revoked list, audit logs, system status, connection history); navigation is consolidated into the header, which already provides this link. Contextual links (e.g. "Revoked List") are kept.

## [1.1.0] - 2026-07-19

### Added

- **Responsive WebUI layout for mobile devices**: navigation collapses to a stacked layout, dashboard cards reflow into fewer columns, and wide tables scroll horizontally within their own container instead of overflowing the page. Desktop rendering is unchanged.

### Fixed

- Approved certificates heading rendered a literal `{count}` placeholder (e.g. `(3 {count} certificates)`) because the count-aware translation string was invoked without its `count` argument. It now reads `(3 certificates)` / `(3 件)`.

## [1.0.0] - 2026-07-19

### Added

- **LDAP-integrated OpenVPN certificate management system** — initial public release
- **Self-service user portal**: certificate request, download, and re-approval request workflow
- **Admin portal**: certificate approval/rejection, revocation, VPN connection history, audit logs, system status
- **LDAP/Active Directory authentication** for VPN connections (certificate + username/password dual authentication)
- **Automated OpenVPN log analysis**: connection/disconnection events parsed every 15 minutes into SQLite
- **Certificate lifecycle management** via EasyRSA 3.x: CA generation, client cert issuance, revocation and CRL management
- **Internal Certificate API** between WebUI and OpenVPN server containers for secure certificate operations
- **Reverse proxy integration**: `Remote-User` / `Remote-Groups` header-based authentication (Authelia-compatible)
- **Multi-language support** (English / Japanese) for WebUI and documentation
- **Configurable admin group** via `ADMIN_GROUP` environment variable
- English and Japanese documentation: SETUP, CONFIGURATION, LDAP_SETUP, TESTING guides
- `.env.example` / `.env.example.ja` with annotated configuration templates

### Security

- CRL validity set to 3650 days by default to prevent silent expiry blocking all VPN clients
- LDAP bind credentials isolated per service (dedicated bind account)
- LDAP settings injected into OpenVPN server config via `setenv` at startup to avoid environment variable leakage
